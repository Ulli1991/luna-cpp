## Porting the in-flight branches

Rules for every branch:

- Port only after the branch has landed on voronoi-cpp main, from a diff against main: pin and hydro go together,
  because the hydro on these branches needs their mesh changes.
- Never copy whole files from a branch. The branches are 19 to 26 commits behind main and hold older copies of notes
  that main has since cleaned (`hydro_design_note.md`, `multigrid_moving_mesh_literature_2026-11-02.md` here).
- Use an allowlist of paths. dim-2d, dim-limiters and dim-1d-diag carry commit `54a007c`, the private note
  `research_notes/proteus_rerun_2026-11-04.md`, which must not reach this repository or voronoi-cpp's main.
- They also carry core dumps, `core.raven01.*` (up to 290 MB each on dim-limiters; added in a951b73 and 10bf520 on
  dim-2d, a3b2aea on dim-1d-diag). Strip them before they land.
- Afterwards: `git grep -il -e proteus -e lucas56098` is empty, `git log --all -- <the note>` is empty.

Steps, with `$OLD` the pin in use here and `$NEW` the voronoi-cpp main that holds the branch:

```sh
OLD=$(git rev-parse HEAD:extern/voronoi-cpp)
git -C extern/voronoi-cpp fetch origin && NEW=$(git -C extern/voronoi-cpp rev-parse origin/main)
git -C extern/voronoi-cpp diff $OLD $NEW -- $PATHS > /tmp/port.patch   # PATHS: the allowlist of the branch
git apply --index --3way /tmp/port.patch
git -C extern/voronoi-cpp checkout $NEW
git add extern/voronoi-cpp
```

Then the CMake and doc edits named below, the gate of stage 1 (build, 0 warnings, ctest, hashes equal to voronoi-cpp
at `$NEW`), and one commit per branch. `git format-patch $OLD..$NEW -- $PATHS` keeps single commits, if that is worth
resolving them one at a time.
